Hopper docs

Everything about porting a Fabric mod to Horizon with Hopper, in plain words.

What Hopper is

Hopper helps move Fabric client mods (Java or Kotlin) to Horizon native mods (Rust). It has four parts:

  • The library: a list of "this Fabric thing is this Horizon thing", one small file per mapping, written by people.
  • The checker: reads a mod and tells you whether it can be ported, and how much of it Hopper understands.
  • The generator and converter: write a Horizon project that builds, with the code Hopper could translate and TODOs for the rest.
  • Finished ports: mods someone already ported, tested and published, so nobody ports the same mod twice.

Hopper is not an official Horizon project. It is made by mod authors, for mod authors.

Checking a mod

  1. Paste a Modrinth link (or just the project's name, like commandkeys) on the check page.
  2. Keep the Minecraft version at 26.3, or change it to check another version's file.
  3. Press Check. Hopper reads the license first. If it allows porting, Hopper downloads the mod's file from Modrinth and reads the names it uses.

Hopper only reads names (which classes, methods and events the mod uses). It never decompiles a mod. Results are kept per mod version, so checking a popular mod again is instant.

What the verdicts mean

Easy
Hopper knows almost everything the mod uses (90% or more), and nothing it needs is missing from Horizon. The starter project gets you most of the way.
Partial
Hopper knows a good part of it (60% or more). The starter project helps, but some of the mod is hand-work.
Needs a person
Hopper knows too little yet. Most mods that change how Minecraft renders or works deep inside land here.
Can't port
The license doesn't allow it, or the mod is obfuscated. Hopper stops here.

Each thing Hopper knows is also marked direct (works the same on Horizon), partial (works differently: the note says how) or missing (Horizon has no API for it yet).

Licenses

Hopper checks the license before anything else:

OK
Open licenses like MIT, Apache or CC0. You may port the mod; credit the original.
Careful
Copyleft licenses like GPL, LGPL or MPL. You may port it, but the port must keep the same license and stay open source.
Stop
All rights reserved, custom, non-commercial or no-derivatives licenses, or no license at all. Hopper doesn't help port these. You can still write your own mod inspired by it, from scratch, without looking at its code.

The starter project

For mods that may be ported, Download starter project gives you a zip with a Horizon mod that builds:

  • horizon-mod.toml and Cargo.toml, pinned to the Horizon build you pick, with the original's license and credits.
  • src/lib.rs with the Horizon hooks the mod needs. Each hook has a TODO saying what the original did there.
  • Code Hopper could convert from the mod's public source code (only when the license allows it). Lines it couldn't convert stay as // TODO (Java): with the original line.
  • Key bindings with the original's default keys, the original's language file and its license.
  • A README.md listing what wasn't ported. Start there.
The starter project is a starting point, not a finished mod. Hopper never builds an .hmod from it, because a mod with empty hooks would load and do nothing.

Finishing a port

  1. Read the project's README.md, then fill in each TODO in src/lib.rs. The notes from the check say what each Fabric thing becomes.
  2. Build it with Horizon's mod tools and fix any errors.
  3. Test it in game, on the Horizon build it's pinned to.
  4. Publish it on the Horizon mod registry, credited to the original mod.
  5. Add it to Hopper's finished ports, so the next person gets it straight away.

Finished ports

When a Fabric mod is already ported, the check page shows Already ported at the top, with who ported it, which Horizon builds it works on, and where to get it. You can see them all on Finished ports.

Ports are only listed once they're tested in game and published on the Horizon registry. To add yours, see ports/README.md.

Normal and Expert

The switch at the top of every page changes how much the check shows:

  • Normal: the verdict in plain words, the license, and the download. For players and anyone curious.
  • Expert: everything: each mapping with its Fabric and Horizon names, the classes and mixin targets Hopper doesn't know yet, and the mod's stats. For modders and contributors.

Your choice is remembered in this browser.

Command line

Everything the site does also runs on your own computer. You need Rust:

git clone https://github.com/hopper-rust/hopper
cd hopper
cargo run -q -p hopper-cli -- check https://modrinth.com/mod/commandkeys
cargo run -q -p hopper-cli -- port https://modrinth.com/mod/commandkeys --out commandkeys-horizon
cargo run -q -p hopper-cli -- port https://modrinth.com/mod/commandkeys --build 8f83e5c --out old-build
cargo run -q -p hopper-cli -- builds
cargo run -q -p hopper-cli -- convert path/to/mod/src

check also takes a .jar file. convert shows what the converter makes of Java source, for trying out rules.

API

The site has a small JSON API: /api/check?mod=<link or slug>&game=26.3 (the report), /api/port?mod=…&build=f1bb66f (the starter project zip; build is optional), /api/builds (the Horizon builds), /api/ports (finished ports) and /api/library (library size). Please be gentle with it.

Contributing

Hopper gets better one mapping, one rule and one port at a time. From easiest to hardest:

  • Add a library entry: one small TOML file saying what a Fabric thing becomes on Horizon.
  • List a finished port: one small TOML file.
  • Add a converter rule: Rust, with a test.

Every name must be real and checked, never guessed. The full guide is CONTRIBUTING.md, and questions are welcome on the Discord.

FAQ

Does Hopper use AI?

No. Hopper is a dictionary and a rulebook: the library is written by people, and the tools only match names and apply rules. Nothing is sent to an AI model, so it gives the same answer every time.

Why doesn't it just give me an .hmod?

Most Fabric mods work by changing Minecraft's own Java code. Horizon is a different game engine written in Rust, so that code doesn't exist there. Hopper can't translate it all automatically, and a mod that builds but does nothing would be worse than no mod. So it gives a modder a head start instead, and points to finished ports when someone has already done the work.

Which Horizon version do the projects target?

You pick it: next to Download starter project, choose the Horizon build you play on (the newest is the default). The project is pinned to that build in its horizon-mod.toml, so it builds against that build's mod API. Its README.md also says the oldest build that has everything the port needs, and warns you if the build you picked is too old for part of it. Horizon's API only grows, so a port usually keeps working on newer builds.

Can I port a mod with an "All rights reserved" license?

No, and Hopper won't help. You can write your own mod with a similar idea from scratch, without reading or copying the original's code, and say it's inspired by it.

Does Hopper decompile mods?

No. The checker only reads the names stored in a mod's file. The converter reads a mod's public source code on GitHub, and only for licenses that allow porting.

What does the site keep?

Check results and starter projects, per mod version, so the same mod isn't downloaded again for every visitor. There are no accounts. Your Normal/Expert choice stays in your browser.

Is Hopper official?

No. Hopper is not made or endorsed by the Horizon team or Mojang.
